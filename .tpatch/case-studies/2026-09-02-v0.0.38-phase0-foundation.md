# v0.0.38 Phase 0 Foundation Gate

## Decision

Keep current upstream T3 Code as the foundation.

Phase 0 proved that the two active fork lineages can move to stable upstream
`v0.0.38` without replacing T3's orchestration, transport, checkpoint,
persistence, terminal, or environment architecture:

- `copilot-cli-provider`
- `session-search`

Orca remains the fallback if recurring upstream reconciliation exceeds the
maintenance budget. Paseo remains the topology-first alternative.

The existing SDK persistence assumption passed:

   using its bundled runtime `1.0.75`.
2. Standalone Copilot CLI `1.0.82` resumed the same session ID and appended a

4. The probe session was deleted after the result was recorded.

This proves native CLI recognition. It does not replace provider behavior,
packaging, or platform tests.

## Runtime Compatibility

`@github/copilot-sdk@1.0.8` declares `@github/copilot` with a compatible
range, but the newest resolved CLI package removed the platform package
`./sdk` export that SDK `1.0.8` still resolves during construction.

Phase 0 therefore pins the SDK's transitive runtime to `1.0.75`. That version
keeps the required platform export while preserving protocol version 3 and
native session compatibility. The lockfile and desktop stage are both checked
for:

- `@github/copilot-sdk@1.0.8`;
- `@github/copilot@1.0.75`;
- the target `@github/copilot-<platform>-<arch>@1.0.75` package;
- `koffi` and its target native binding.

## Feature Scope

Phase 0 reduced the active reconciliation DAG to two independent roots.

Copilot runtime concerns such as commands, dynamic models, plan/compaction,
skill discovery, text generation, tool detail, timing, current UI, usage, and
packaging were folded into the provider root.

The following remain outside the active Phase 0 DAG:

- Verify then retire: WSL/managed environments, background-task UI, generic
  hidden-model behavior, cross-platform packaging lineage, toast close.
- Defer: skill controls, rich resource rendering, tool-result expansion,
  custom agents, effort theming.
- Unrelated: system-generated turns.

Historical dependency edges were removed so these records no longer gate the
two active roots. Their stale reconcile labels remain historical metadata and
must not be interpreted as current source failures.

## Semantic Ports

### Copilot provider

The current provider uses canonical driver kind `githubCopilot`, while decoding
legacy `copilot` settings and instance records.

It uses the official SDK and current T3 driver/runtime/settings architecture for:

- native create/resume/stop/interrupt;
- model and reasoning option discovery;
- approvals, user input, plans, attachments, skills, MCP, commands, tools,
  tasks/subagents, compaction, and usage;
- current web/mobile/settings presentation;
- bounded text generation and cleanup;
- target-aware external native dependency staging.

Independent review found and fixed streaming whitespace corruption, subagent
root-message pollution, shutdown races, hidden text-generation sessions,
misleading approval scopes, incomplete usage accumulation, home-identity
mismatches, custom-instruction trust behavior, cross-project skill leakage,
legacy default deletion, plan deduplication, compaction projection, teardown
deadlocks, resume ownership conflicts, and Effect interruption leaks.

### Session search

The search port avoids `ChatView.tsx` and runs inside the current virtualized
timeline. It adds:

- `Cmd/Ctrl+F` and command-palette entry points;
- loaded-window search over messages, plans, and visible activities;
- bounded page-by-page earlier-history loading;
- deterministic wrapped navigation and targeted row reveal;
- accessible active-row highlighting;
- IME-safe input and correct command-palette focus handoff.

Exact inline marks, automatic full-history occurrence indexing, and mobile
entry points remain deferred rather than falsely claimed.

Independent review found and fixed stale hidden activity matches, palette focus
theft, IME interception, and omitted live `task.progress` rows.

## Tpatch Landing Lesson

Feature commits created before `tpatch land` do not provide a usable
single-parent replay anchor. Parallel landing histories for the same slug are
also unsafe: the verifier rejects reachable landing candidates that describe
different patch generations, even when the newest attestation is exact.

The final solution was:

1. Start one clean integrated history from `d01f4d65f`.
2. Carry forward the audited metadata and current byte-exact canonical
   artifacts without feature source.
3. Materialize and land `session-search` once.
4. Materialize and land `copilot-cli-provider` once.
5. Verify both roots against those sequential single-parent anchors.
6. Activate the clean history only after its non-tpatch tree matched the
   previously tested integration byte-for-byte.

The final landing commits are `05b8dce9f` for search and `6e81ba0c9` for
Copilot. The superseded integration history remains under
`reconcile/v0.0.38-phase0-history` as audit evidence rather than reachable
landing ancestry.

Repository commit hooks must not format canonical patch artifacts. Formatting
the patch changes its hash and invalidates landing evidence. The verified
metadata commit therefore bypassed hooks intentionally and recorded that
reason.

Historical recipes that predate these ports remain explicitly stale.
`artifacts/post-apply.patch` is the authoritative replay intent.

## Packaged Electron Lesson

The first arm64 artifact exposed a desktop-only runtime boundary. The SDK's
default stdio path launches the platform JavaScript entry with
`process.execPath`. In the packaged backend, `process.execPath` is the branded
Electron executable running with `ELECTRON_RUN_AS_NODE=1`; Copilot's CLI
argument parser rejected that Electron-hosted child before stdio startup.

The provider now resolves the target package's native executable when running
under Electron and rewrites archive paths from `app.asar` or `server.asar` to
their smart-unpacked sibling. Explicit user CLI paths and explicit in-process
SDK transport still win. Unit coverage includes macOS, Windows `server.asar`,
and Linux musl fallback paths, and the mounted DMG proves the real macOS path.

## TWS and Push Decisions

TWS v1.2.14 remains an exact-version, read-only topology and operational-health
source. The product owns environment, repository, feature binding, worktree,
provider-session, and attention identity.

Phase 0 adds no notification service. Local, LAN, NetBird, Tailscale,
WireGuard, and desktop-managed SSH operation must work without T3 Connect,
Clerk, Cloudflare, APNs, or FCM.

Official T3 Connect remains optional. Private APNs/FCM requires an explicit
gateway and matching custom-signed mobile applications. Future notification
payloads must contain opaque IDs and category codes rather than project,
thread, prompt-derived, model, path, tool, or error detail.
